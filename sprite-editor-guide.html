Sprite Editor — Chromebook Guide

Tesco Trueno · everything you need to build characters and never lose them

Four lines, then you can ignore the rest of this.

  1. open a sprite file, work on it, press save. Save writes straight back into the file you opened. Nothing else is stored anywhere — close the tab without saving and the changes are gone.
  2. One file at a time: living.sprite.js is the people and animals, vehicles.sprite.js is everything with wheels.
  3. Instant backup: press text, Ctrl+A, Ctrl+C, paste into a Google Doc. Four seconds.
  4. save again before you close the tab. Every time.

The Chromebook restarts itself for updates without asking. That is how people lose an afternoon.

Before you set out

Three files travel together:

  • sprite-editor.html — the workshop
  • sprites/living.sprite.js — the people and animals: grannies, shoppers, Trolleyboy, the managers, the gulls, the fox, and the umbrellas they carry
  • sprites/vehicles.sprite.js — everything with wheels: Trueno, the four kinds of car, the trolley, the bus, the recovery truck, the lorry, and the parking ticket

Download all three. They arrive in My Files > Downloads.

Open the Files app, make a folder in Google Drive called trueno, and drag them into it.

Downloads is local storage. Nothing backs it up, and a powerwash empties it. Drive is safe ground. Work from Drive.

Ignore the .js on the end of the sprite files. They are not programs; they are the same plain text as always, with one extra line round them so the game can load them straight from a folder. The editor takes that line off when you open the file and puts it back when you save.

Entering the workshop

In the Files app, right-click sprite-editor.html and choose Open with > Chrome.

That is the whole install. It is one HTML file with no dependencies — nothing downloads, nothing phones home, and it works with the wifi off. The address bar will say file:/// rather than a website, which is correct.

Bookmark the tab once it is open. It is faster than going through Files every time.

It will be a black screen with an empty grid. That is right: the editor starts with nothing in it.

Loading the cast

Press open and pick one of the two sprite files from your Drive folder. Its characters appear in the dropdown at the top left — open living.sprite.js and you get the grannies, shoppers, staff, gulls and the fox; open vehicles.sprite.js and you get Trueno, the cars, the bus, the truck and the rest.

Chrome may ask whether the editor can see and save the file. Say yes — that is what lets save write straight back into it.

Drag the background to spin the view, scroll to zoom, and press fit if something goes off screen.

Worth knowing what the file actually is: plain text you could open in any editor. One line per box, like this:

box 0.42 0 0.55  1.9 0.62 0.28  paint  n=bonnet top=#e8e8e8

Position, then size, then colour, then optional extras. There is a full explanation of the format written into the top of the file as comments.

This matters for one reason: if the editor ever breaks, your work is still readable text. Nothing is locked in a proprietary format. (If you ever edit one by hand, only change what is between the two backtick ` marks — the line above and below them is the wrapper the game needs.)

Building a character

Everything is made of boxes. No curves, no meshes — you are working in the same vocabulary as a Lego minifig, and the charm is in what you can imply with eight or ten blocks.

The panels, left to right:

  • sprite — the character. new, dup, rename, del.
  • states — versions of the character, as tabs. The granny has three looks — hunched, rigid and round — and each person in the game is given one and keeps it. dup a state and change it to make another.
  • boxes — the blocks in the current state.
  • properties — the selected box: position, size, rotation, colour.

Moving things

Click a box to select it. Hold and drag to move it, and it locks to one axis depending on which way you pull. Click a box that is already selected to pick a single face, then drag that face to resize in that direction. Click the background to drop everything and just look at it.

Arrow keys nudge the selected box by 1 cm. Hold Shift and they resize instead. D duplicates, Backspace deletes, Ctrl+Z undoes.

For up and down the keys are PageUp and PageDown, which a Chromebook does not have — Alt + ↑ and Alt + ↓ normally stand in. If that fights you, type the number into the z base field instead. The number fields always work.

Colour

Each box has a base colour, and each of its six faces can override it. Faces are named in the box's own frame (fwd, aft, lft, rgt, top, bot) so they stay correct when you rotate it. Alpha is a separate 0–100 box, and none makes a face invisible — which is how you make something hollow, like the inside of a trolley.

Named colours: paint, skin and hair

Some colours are not decided by the sprite at all. Every car in the game has its own paint, and every person their own skin and hair, chosen once and kept — so the same granny always turns up with the same grey hair in the same silver Jazz. To make a box take one of those, set named (under the colour picker) to paint, skin or hair.

The number beside it is a shade: 1 is the colour as chosen, 0.75 is a quarter darker. The cars use that for their sills, so the sill is always a darker version of whatever colour the car is.

The three previews swatches only change what you see while you work — try a red car, or a different skin tone, to check the sprite looks right in all of them. They are not saved.

Which boxes should be named: on a car, the bodywork (paint), the sills (paint at 0.75). On a person, the head, neck and any bare arms (skin) and the hair (hair). Leave clothes, glass, tyres and lights as fixed colours.

Lights: lit

The lit field, from 0 to 1, makes a box glow: it keeps its colour at night instead of going dark with everything else. Headlights, tail lights, the bus's destination blind, the truck's beacons. Most boxes are 0.

Three buttons that save you pain

  • no burying is on by default. It stops you hiding a box completely inside another one, where it costs memory and shows nothing.
  • ground to z=0 drops the whole sprite so its feet sit on the floor. Use it whenever something looks like it is hovering.
  • scale with apply resizes the entire character uniformly. Build at whatever size feels natural and fix it afterwards — or set a real-world height and press fit.

The mass field is in kilograms, for the physics later. Rough is fine. Per-box weight and balance are worked out from the shapes, so they survive scaling.

Size, anchors and parts

The size, anchors & parts panel on the left describes the whole character rather than one box.

  • size is the footprint and height the game uses for the character — how much room it takes up, how tall it is. Press from boxes and it is measured for you; it shows as a dashed outline on the ground.
  • Anchors are named points the game hangs things on: where the parking ticket goes on a car's roof (ticket), where a towed car sits on the truck (bed), where people get on the bus (door), where the lorry's trailer hooks on (hitch). They show as pink crosses with their names. add anchor puts a new one on top of the selected box; type its name and nudge the three numbers (forward, side, height). The names matter — the game looks them up by name, so a car without a ticket anchor gets its tickets in a guessed spot.
  • Parts are groups of boxes that will one day move on their own — a gull's wings, an umbrella, the truck's tipping bed. Give a box a part name in the box panel on the right and it joins that part; the part's pivot shows as a blue ring and can be moved in the left panel. Nothing in the game moves parts yet, so this is for later.

Open, merge, save

The buttons along the top.

ButtonWhat it doesSafe?
openThrows away everything in the editor and opens a sprite file insteadOnly if you have saved. This is the dangerous one.
mergeAdds another file's characters alongside what you already haveYes
saveWrites everything straight back into the file you openedYes — that is the point of it
save asDownloads a copy, without touching the file you openedYes

The trap

open replaces. merge adds.

If you have spent two hours on a fox and then press open without saving, the fox is gone. No warning, no undo prompt. Save first, every time you open something else.

And keep the two files apart: work on living.sprite.js or vehicles.sprite.js, not both at once. If you merge the cars into the people file and press save, the cars end up in the people file too — the game will still work, but Dad will have some untangling to do.

What merge does with clashing names

Nothing destructive. If you merge a file containing gull and you already have a gull, the incoming one becomes gull-2. Both survive and you rename whichever you prefer. Merge never overwrites a character.

When save downloads instead

On a Chromebook in Chrome, save writes back into the file you opened (the first time, Chrome asks if that is all right — say yes). If you opened the file some other way, or the browser does not allow it, save downloads a copy instead, named after the file. Chrome will not overwrite a download, so you get living.sprite (1).js and so on. If that happens: put the newest one in your trueno folder, rename it back to exactly living.sprite.js (or vehicles.sprite.js), and open it from there next time.

The instant save

The text button shows everything currently open as plain text. Click in it, Ctrl+A, Ctrl+C, and paste into a Google Doc or Keep note.

No download, no file naming, about four seconds. If you are about to try something risky, do this first. Paste it back into the same panel and press apply to restore, or merge to bring it in alongside.

A routine that never loses anything

Four habits. They take about ten seconds each.

  1. Start: open the editor, open the one sprite file you are working on.
  2. Before anything experimental: save as, so there is a copy from before. Every finished character: save.
  3. Every twenty minutes or so: text, select all, copy, paste into one running Google Doc. Do not delete the old pastes — that Doc becomes your version history for free.
  4. End: save before you close the tab. Always. Even if you think you changed nothing.

The Chromebook restarting itself for an update is the thing that catches people. It does not ask.

Sending work back

Send the sprite file you worked on — living.sprite.js or vehicles.sprite.js — straight out of your trueno folder. If you would rather send just your new characters, save as a copy with a name like yourname-fox.sprite.js and send that; Dad merges it in, so nothing of yours is overwritten and nothing of his is either.

New characters do not need to relate to anything already in there. A car park is a broad church. (If one needs to appear in the game as well as in the file, tell Dad its name — the game has to be told what a new character is for.)
